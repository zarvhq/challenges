# Zarv Engineering Challenges

Welcome to our Engineering Challenges repository 🖖

If you found this repository it probably means you are participating in our recruitment process. Thank you for your time and energy. If that's not the case, take a look at our [openings](https://www.linkedin.com/company/zarv/jobs/) and apply!

This is an opportunity for both of us to work together and get to know each other in a more technical way. If you have any questions please [open an issue](https://github.com/zarvhq/challenges/issues/new) and we'll reach out to help.

## Before you start coding, read this 😎

Before jumping into the implementation, take a moment to think about the solution. We will evaluate not only whether your solution works, but also the following aspects:

- Simple, easy-to-read code. Remember: simple is not the same as easy.
- Comments where the code is non-obvious. The clearer the complex parts are, the faster and more positive our feedback will be.
- A `README.md` that briefly describes how to build, run, and test your code.
- Consistency throughout your codebase.
- Feel free to include considerations about your solution. Use the language specified in each challenge; if you'd like to use a different language, reach out first 🙏.

**Good luck** and may the Force be with you! 👊🏼

## How to submit your challenge

1. Fork this repository, read the challenge carefully, and take your time to think about the solution.
2. Follow the acceptance criteria described in the challenge folder.
3. Document your findings — how did you approach the challenge?
4. Help us run your code; we'd love to see it in action.
5. Open a Pull Request with your solution once you're ready.
